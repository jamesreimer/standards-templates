# Security Policy

## Scope

Security reports are appropriate for vulnerabilities in this repository's
Python scripts, GitHub Actions workflows, dependency or update automation, Git
hooks, and other executable tooling. Tests are in scope when a defect in them
materially affects a validation or security assumption.

Ordinary software bugs, standards-content disagreements, documentation
corrections, and general support requests should use a regular repository
issue. Normative standards text is documentation and is not represented as
security-reviewed software.

## Reporting a vulnerability

When exploit details could create risk, use GitHub's private vulnerability
reporting for this repository:

<https://github.com/jamesreimer/standards-templates/security/advisories/new>

Include the affected component, impact, reproduction conditions, and any known
mitigation. If private vulnerability reporting is unavailable, contact the
repository owner through a private method listed on the owner's GitHub profile.
If no private method is available, open a brief public issue requesting private
contact without including exploit details.

This repository does not offer a bug bounty, response-time guarantee,
supported-version matrix, security certification, or formal coordinated
disclosure program.
