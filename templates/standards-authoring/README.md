# Standards Authoring Template

Stable template ID: `standards-authoring`

Human-facing title:

> **Standards and Policy Authoring Standard**

## Purpose

This template defines a disciplined authoring model for organization-owned standards and policies so that normative documents are clear about scope, authority, requirement strength, informative material, external basis, exceptions, and revision.

It is intended for organizations that want consistent normative documents without forcing every subject into one writing style or mistaking strict wording for good governance.

## Source document

The reusable template is [`standard.md`](standard.md).

## Adoption

Adopt this template into an organization-owned standards source through deliberate review.

The adopted copy becomes authoritative only for the scope assigned by the adopting organization. This repository remains provenance and a possible source of later improvements, not continuing authority.

See the repository-level [ADOPTION.md](../../ADOPTION.md) and the reusable [`standards-adoption-model`](../standards-adoption-model/) template for the adoption boundary.

## Likely organization-specific review points

Before adoption, an organization should consider whether it needs to adapt:

- the document types it recognizes, such as Standard, Policy, Guideline, or Specification;
- approval roles or governance bodies;
- exception authority;
- citation and evidence requirements;
- required document metadata;
- review cadence or lifecycle mechanics governed elsewhere;
- whether BCP 14 keywords are mandatory in all normative clauses or only where requirement strength needs explicit signaling.

The template deliberately does not prescribe a document-management platform, repository layout, or approval workflow.

## Conceptual boundary

This template governs **how normative documents are written and calibrated**.

It does not independently govern:

- how external templates become organization-owned authority;
- where project artifacts or planning state belong;
- the complete lifecycle or retention model for controlled documents;
- the exact approval workflow used to change a canonical artifact.

Those subjects remain separate where distinct consequences justify separate standards.
